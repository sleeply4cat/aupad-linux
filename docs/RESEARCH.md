## 1. Qualcomm EUD — отладка через USB-C

- EUD (Embedded USB Debug) — аппаратный блок Snapdragon, дающий SWD/JTAG, trace и
  COM-консоль через обычный USB-C кабель, без UART-проводов и вскрытия корпуса.
  В открытых реализациях по-разному зрелые: SWD в основном OpenOCD — единственный
  завершённый end-to-end сценарий; JTAG — эксперимент; TRACE — активно дорабатывается;
  COM — target-side есть в downstream-ядрах, готового host-клиента нет.
  *(полный текст: archive/Qualcomm_EUD_исследование.md)*
- Внедрение на AuPad — end-to-end: stub включает EUD через **SCM-вызов** (mode_mgr2
  `0x1612000` + CTLOUT `0x1611014`), регистр переживает любые сбросы; Linux и U-Boot
  дают двунаправленную консоль `ttyEUD0`, host-логгер `tools/eudlog.py` переживает
  ребуты и паники, OpenOCD-патч в `tools/ocd/` даёт SWD/GDB на SM6225.
  *(полный текст: archive/AuPad_EUD_аудит.md)*
- **Прямая запись в `0x1612000` из Linux = доступ к secure-регистру = мгновенная
  паника.** Легальное выключение на живой системе — только SCM: `tools/devicetests/eudoff.ko`
  (`qcom_scm_io_writel`). Но resume с реально выключенным femto-PHY висит за ~2 с:
  EUD не блокер линка — он тем, что держит USB-PHY живым через suspend. **EUD остаётся включённым.**
- Консоль: geni-UART (`console=ttyMSM0`) слепой (приёмника нет) и вешает дисковые
  загрузки; **EUD COM — единственная видимая консоль**. Никогда не совмещать
  `keep_bootcon` с `console=ttyEUD0` — два писца на один FIFO.

## 2. EDL reboot из работающей системы

- `adb reboot edl` **не пишет ничего в PON spare**: для EDL у Qualcomm отдельный канал —
  бит «download mode» в TCSR `BOOT_MISC_DETECT` (на Bengal/Khaje — `0x3D3000`), ядро
  пишет его **через SCM-вызов** и делает тёплый сброс; XBL на следующем старте уходит
  в QDLoader 9008. Значения: `0x00` off, **`0x01` EDL**, `0x10` full dump, `0x20` minidump
  («`0x10` = EDL» — распространённая ошибка).
- В vanilla 7.3.1 механизм почти готов (`qcom_scm` умеет RMW в `BOOT_MISC_DETECT`),
  но маска `GENMASK(5,4)` не даёт бит 0. Воспроизведено патчами **0033** (DT
  `qcom,dload-mode`) + **0034** (параметр `edl`):
  `echo 1 > /sys/module/qcom_scm/parameters/edl && reboot -f`. Железно проверено 2026-11-13.
- Выход из EDL без кнопок: `tools/ocd/srst` (SRST из EDL → нормальная загрузка).
  *(полный текст: archive/Qualcomm_EDL_reboot_исследование.md)*

## 3. Фронтальная камера GC5035

- Сенсор **всегда был на шине, по адресу 0x37** — но 0x37 попадает в зарезервированный
  SMBus-блок 0x30–0x37, который `i2cdetect` по умолчанию не опрашивает: все прежние
  сканы (наши и стокового Android) его пропускали. Адрес нашёлся только сырым чтением
  регистра ID по всем 112 адресам при драйвере, который сам держит секвенсацию питания.
- В mainline драйвера GC5035 нет; портирована LKML-серия v2 Nicola Fiorillo
  (проверена автором на другом Chuwi с той же камерой; происхождение таблиц —
  intel/ipu6-drivers ← серия Tomasz Figa 2020). Оригиналы серии: `sources/gc5035-lkml/`.
- Серия ACPI-only → патч **0038** добавляет OF-match `galaxycore,gc5035` +
  `i2c_device_id`, патч **0039** — DT-узел `camera@37` в `cci_i2c1`. Итого камера =
  патчи 0035–0039, работает в приложениях (2592x1944@30 + биннинг через csiphy2).
- MCLK: сток-таблицы предполагают 24 МГц, драйвер требует 19.2 МГц — на 19.2 всё работает.
- Грабли: номера CCI-шин меняются между загрузками (не хардкодить имя сущности);
  libcamera-клиенты хватают камеры на старте (`kill wireplumber snapshot` перед ручной
  работой); после оборванного STREAMON сенсор остаётся в streaming — лечится
  unbind+bind драйвера. *(полный текст: archive/GC5035_фронтальная_камера_исследование.md)*

## 4. Энергосбережение: этапы и итог

План из 8 этапов (archive/Энергосбережение_исследование.md §5) исполнен так:

| Этап | Итог |
|---|---|
| A. Диагностика сна | снапшоты RPM-мастера из DTB планшета, votes-исследование (§5) |
| B. USB resume | **0040** dwc3-qcom UTMI PIPE clock — работает |
| C. UART RX | отменён пользователем: UART-адаптера нет и не будет |
| D. Whole-chip sleep (vlow/vmin) | закрыт как N/A: **полный паритет со стоком** — у Android vlow/vmin Count = 0 тоже |
| E. Wake-источники | MPM из дерева qcm2290 (0042/0043): power-button и RTC будят точно |
| F. ADSP/сенсоры | elogind-хук останавливает sensorspd-сервисы на время сна |
| G. Зарядка | **0046/0047**: threshold→float-voltage, FCC, ICL; железно проверено; регистры сверены verbatim по `sources/smb5-downstream/` (тот же PMIC PM7250B) |
| H. Suspend для пользователя | elogind sleep.conf + хуки, финальный rebind `4ef8800.usb` после сна |

- Флаги `clk_ignore_unused`/`pd_ignore_unused` **сброшены** из cmdline: с 0045
  (skip clock-handoff голосов smd-rpm) звук поднимается и GPU переживает циклы
  suspend без них. Голоса прокси не были блокером — настоящие держатели XO:
  remoteproc'ы и femto-PHY, питаемый EUD.
- Хронология и железные тесты: [PORT.md](PORT.md), разделы Power.

## 5. RPM Client Votes — семантика байтов

- Публичной таблицы нет (расшифровка в закрытом rpm_proc). Семантика от Qualcomm
  (Maulik Shah, QTI, LKML-серия для qcm2290): **каждый байт = xo-clock голоса одной
  подсистемы**; bit7 = маркер валидности; vlow = XO-off на весь SoC, vmin добавляет
  минимизацию рельсов.
- Алфавит байтов {81, 83, 85, 87}; полы: радио 0x83878381, wifi+bt при rfkill-off
  0x85818581. «Настоящий сон» 0x81 на APSS сбрасывается только на финальном WFI.
- Метод наблюдения: `tools/devicetests/votes_nrq.c` — freeze_noirq/resume_noirq на
  фейковой platform-платформе (syscore при s2idle не запускается, чтения после
  пробуждения всегда поздние). freeze == resume всегда.
- **Сырый freeze без elogind-хука валит ADSP sensorspd** (frpc_dsp fatal + WARN-шторм) —
  циклы сна только через хук-путь.
- Сравнение со стоковым Android 15: vlow/vmin Count = 0, APSS xo_count = 0, mem_sleep =
  s2idle — паритет; сток при этом сам `echo mem` не проходит (ssusb EBUSY с adb),
  наш pmOS спит и будится по RTC с живым гаджетом.
- Данные и артефакты: archive/votes-20261114/ (README — метод и таблицы дня,
  BYTES.md — раскладка, DOWNSTREAM-DECODE.md — расшифровка, misc-backup — путь
  возврата на Android через /dev/block/bootdevice/by-name/misc).
