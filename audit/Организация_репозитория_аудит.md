## 1. Сводка

Проект в хорошем содержательном состоянии (серии патчей синхронны с деревьями, коммиты единообразны,
PORT.md фактический и плотный), но организация захламлена следами сессий:

1. **Корень репозитория замусорен неотслеживаемыми файлами на ~660 МБ**: дампы памяти планшета (`memory/`,
   488 МБ), tarball исходников ядра (155 МБ), vendor-справочные файлы с мусорными именами (`rrr54.c`),
   машинный конфиг EDL. Всё это видит `git status` и зацепит `git add -A`.
2. **Серия патчей отстаёт от git на один файл**: `patches/linux/0044` применён к `linux/` и существует
   на диске, но не закоммичен; сам `main` при этом не запушен (впереди 1 коммит).
3. **Три забытых клона U-Boot** в `build/` (рабочий + битый fetch на 51 МБ + пустой каталог).
4. **README-рецепт сборки противоречит сам себе** (база mt6735 7.3-rc3 в рецепте vs vanilla v7.3.1,
   на которой патчи тестировались и из которой собрано локальное дерево); мёртвая ссылка на `run.sh`.
5. **Критичная операционная информация живёт только в памяти агента** (бэкап, пароль планшета, сетап
   хоста, quirks EDL) — в репо её нет вообще.
6. **Git-репозитории портов (`linux/`, `build/uboot/`) не имеют remote** — единственная копия истории
   порта (46 коммитов ядра) — локальный диск + файлы-патчи.

## 4. Документация и инструкции

### 4.1 README: рецепт сборки противоречит сам себе (реальный баг доков)

- Утверждение: «The patches apply to upstream Linux v7.3.1 and were tested there».
- История одной фразой: «first developed on mt6735-staging at a62a3e8f9 … 7.3-rc3».
- А в рецепте: `git clone https://gitlab.com/mt6735-mainline/linux.git && git checkout -b aupad a62a3e8f9 && git am`.

То есть рецепт собирает дерево на **mt6735 7.3-rc3**, хотя патчи тестировались и применяются к **vanilla
v7.3.1**, и именно так собрано локальное `linux/` (коммит `a1a4e1fab «Linux 7.3.1 vanilla»` — import из
tarball `linux-7.3.1.tar.xz`, валяющегося в корне). Рецепт воспроизводит не то дерево, с которым работаем.

### 4.2 Мёртвые ссылки и устаревшее

- `build/ub.sh:3` — «Same verdicts as `run.sh`» — `run.sh` не существует ни в build/, ни в tools/.
- README What's here: строка про `tools/` неполная (см. 3.3); `docs/` описана как «Engineering notes» —
  одного файла PORT.md, больше в docs/ ничего нет и индекса нет.

### 4.3 PORT.md

Плотный и фактический — SRST/EDL-матрица, quirks edl-клиента, ловушки OpenOCD всё задокументированы
(строки 567–586). Проблемы только структурные:

- 587 строк / 70 КБ монолит без оглавления; секции-лог с датами («Suspend and power (2026-10-31)») —
  хронология смешана с актуальным состоянием (например, два раздела Power: 347 и 227).
- README ссылается на него трижды по якорям — работает, но без оглавления в самом файле навигация
  только через Ctrl-F.

### 4.4 Операционная информация, существующая ТОЛЬКО в памяти агента

Проверено grep'ом: в README.md и PORT.md нет ни одного из этих фактов (grep `~/111`, `backups/`,
`147147`, `/home/kirill` — пусто):

- путь к полному бэкапу `~/111/backups/aupad-20261112`;
- пароль планшета;
- сетап хоста: Ubuntu 24.04, кросс-gcc + fastboot + edl (patched clone + quirks) + patched OpenOCD в
  `tools/ext`, отсутствие sudo, user-level NetworkManager;
- quirks EDL-тестинга (короткие таймауты firehose — hang = bug; лишние переинсталляции не делать);
- рабочий протокол сессий (сверка git status внешнего + субрепо на границах фаз, арифметика с
  ведущими нулями — октальная ловушка).

Риск: смена машины или работы без агента — и это знание исчезает. Оно рассеяно по трём местам:
memory-файлы агента, `.zcode/plans/`, аудит-доки. В репо — ничего.

### 4.5 Разнобой состояний audit/

2 дока закоммичены (GC5035, Энергосбережение), 3 нет (AuPad_EUD_аудит, Qualcomm_EDL_reboot,

## 6. План исправлений

Принципы: никаких `rm` — только перемещения и .gitignore (удаления мусора — вручную пользователем);
каждая фаза независима и безопасна по отдельности; ничего из этого не выполнялось в этой сессии.

### Фаза 0 — git-безопасность, ~15 мин (P0)

1. `git add patches/linux/0044-*.patch` + коммит (например `patches: add 0044, dwc3 qcom-legacy UTMI resume`).
2. `git push origin main` (висит power-коммит 3d2bfbd + новый).
3. Решение: `git push origin --delete readme-status` — ветка полностью влита в main
   (проверено `merge-base --is-ancestor`), уникального контента нет, README в ней устарел («7.3-rc3»).
4. Добразить 3 аудит-дока в git (политика уже есть); dmesg-лог переместить в `logs/`.
5. Открытый вопрос: RU-доки в публичном репо — прецедент уже есть, но решение стоит зафиксировать явно.
