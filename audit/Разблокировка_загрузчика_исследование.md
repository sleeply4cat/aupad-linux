# Разблокировка загрузчика AuPad: почему fastboot-команды не работают и как разблокировать без правки devinfo

**Дата:** 14 ноября 2026 года
**Предмет:** реверс стокового ABL из дампа (`~/111/backups/aupad-20261112/abl_a.bin`): судьба команд `flashing unlock` / `oem unlock` (вырезаны / спрятаны / сломаны), устройство unlock-движка, хранилище флага разблокировки и пути разблокировки без ручной правки devinfo.
**Материал и метод:** статический разбор бинарников бэкапа (ABL, uefivarstore, devinfo, dip/secdata/limits, xbl/imagefv/uefisecapp — поиск строк), дизассемблирование AArch64 (capstone, ставился в user-scope: `pip install --user --break-system-packages capstone`). На планшете ничего не выполнялось, файлы проекта и памяти не менялись.
**Структура abl_a.bin:** ELF AArch64 (точка входа 0x9fa00000) → FV FFS2 @0x3000 (0x32000 байт) → GUID-defined секция LZMA (`EE4E5898-3914-4259-9D6E-DC7BD79403CF`) → внутренний FV (0x7d0c0) → FFS `f536d559-459f-48fa-8bbc-43b554ecae8d` (type FV-IMAGE) → RAW-строка `LinuxLoader` + PE32 ABL.efi (ARM64, SizeOfImage 0x7d000). **Все адреса ниже — смещения внутри распакованного abl.efi** (ImageBase=0, VA == файловое смещение); внутри PE лежит сжатым только сам ABL, xbl/imagefv/uefisecapp дополнительно не распаковывались.

## 1. Вердикт (главная таблица аудита)

| Вопрос | Вердикт | Доказательство |
|---|---|---|
| `flashing unlock`, `flashing lock`, `flashing get_unlock_ability` | **ВЫРЕЗАНЫ из интерфейса** | строк-имён нет нигде в образе (ни ASCII, ни в таблице команд); матчиться нечему → fastboot отвечает unknown |
| `oem unlock`, `oem lock` | **ВЫРЕЗАНЫ** | то же: строк нет, в таблице команд отсутствуют |
| Сам unlock-движок (set state, persist) | **СПРЯТАН, но цел и жив** | диспетчер поддерживает внутренние типы команд {5,6,7,9} (маска `0x3a0`) → `SetDeviceUnlockState` → `SetUnlockDeviceState` → persist через VB-протокол; все debug-строки цепочки живы |
| Сломано ли | **Нет — сознательная сборка OEM** | код симметричен и рабочий; удалены только имена команд из регистрируемой таблицы + строки; на их месте добавлены свои oem-команды (set-hw-fence-value, set-gpu-preemption) |
| Почему «команда не работает» у пользователя | не матчится ни с одной из 13 зарегистрированных команд | полная таблица команд — в §3 |
| `flashing unlock` в нашем U-Boot | **Не реализован в сборке** (отдельный вопрос, не про ABL) | в `drivers/fastboot/fb_command.c` он есть upstream, но регистрируется только при `CONFIG_FASTBOOT_CMD_FLASHING`, которого в `configs/qcom_defconfig` нет; и на ABL он всё равно не влияет |

## 4. Как разблокировать без правки devinfo

Ключевой факт: любое «ручное» изменение состояния = запись devinfo (единственное живое хранилище; uefivarstore/dip/secdata пусты). Единственный способ **выполнить** разблокировку, не редактируя devinfo руками, — заставить сам ABL выполнить легальный unlock через спрятанный движок. Движок пишет devinfo сам, штатным каналом VB-протокола — наша правка остаётся только в `abl_a/abl_b`.

| Вариант | Суть | Какие разделы правим | Риск | Статус |
|---|---|---|---|---|
| **A (рекомендуемый): патч ABL — перехват oem-обработчика** | заменить первые 3 инструкции обработчика `oem set-gpu-preemption` (0x47da4) на заглушку `mov w0,#0; mov w1,#1; b 0x182dc` → команда выполняет легальный unlock (is_unlocked=1) через живой движок, ABL сам персистит devinfo | только `abl_a/abl_b` (devinfo не трогаем) | переподписание/repack FV; тест только на неактивном слоте; откат — из EDL | спланирован, не проверен |
| **B (нулевой патч, проверка гипотезы type=index): `fastboot oem set-gpu-preemption x`** | если FastbootLib назначает тип команды = индексу в таблице, то тип 5 = `oem set-gpu-preemption` уже сейчас попадает в маску {5,6,7,9} → SetDeviceUnlockState(5) = **unlock без всякого патча**; тогда же `oem device-info` (тип 6) лочил бы и не печатал | ничего | проверка безопасна: даже если гипотеза верна, состояние меняется штатным движком и откатывается командой-парой | гипотеза, проверить первой |
| C: правка devinfo напрямую | исключено условием задачи; вдобавок в хвосте devinfo есть 40 байт хэша — VB-драйвер может отвергнуть неконсистентную правку (не проверено) | devinfo | — | отклонено |
| D: uefivarstore / dip / secdata / limits / mdtp | хранилищ unlock-состояния не содержат (проверено сканом дампов); mdtp не provisioned | — | — | отклонено |
| E: U-Boot `CONFIG_FASTBOOT_CMD_FLASHING` | U-Boot-овский `flashing unlock` не влияет на ABL и вообще не persистится в devinfo | — | — | отклонено |

### 4.1 Патч A (точные байты)

По адресу 0x47da4 (текущее тело `CmdOemSetGpuPreemption`, функционально на планшете не нужно):

```
0x47da4: 00 00 80 52    mov w0, #0      ; arg0: 0 → поле is_unlocked
0x47da8: 20 00 80 52    mov w1, #1      ; arg1: значение = TRUE (unlock)
0x47dac: 4C 41 FF 17    b   0x182dc     ; SetUnlockDeviceState(0, 1) → is_unlocked = 1
```

(переход назад на 0x2FAD0; для `unlock_critical` — второй обработчик `oem set-hw-fence-value` 0x47c94: `mov w0,#1; mov w1,#1; b 0x182dc` → `20 00 80 52 / 20 00 80 52 / 90 41 FF 17`.)

Процедура: распаковать FV→LZMA→PE (скрипт /tmp/zscripts/fvparse.py + dd из этой сессии), внести 12 байт, собрать обратно (lzma FORMAT_ALONE, восстановить GUID-defined секцию и размеры), записать в **неактивный слот abl** по EDL/firehose, переключить слот, проверить `fastboot oem set-gpu-preemption x` и `oem device-info`. Подпись: hash-сегмент ABL несёт тестовую цепочку Qualcomm — если XBL проверяет подпись, переподписать тем же тестовым ключом (сек,image test key); если проверка провалится — планшет просто не загрузится до отката из EDL (9008 доступен всегда, откат гарантирован).

### 4.2 Проверка B (безопасная, первая)

1. Попасть в fastboot стокового ABL: из Linux `reboot bootloader` (PON `SOFT_RB_SPARE`, см. [Qualcomm_EDL_reboot_исследование.md](Qualcomm_EDL_reboot_исследование.md)) или из U-Boot `fastboot reboot-bootloader`.
2. `fastboot oem device-info` — если печатает блок `Device unlocked: …` → гипотеза type=index неверна, работаем по варианту A. Если ответа/печатей нет и после ребута состояние изменилось — гипотеза верна, и `fastboot oem set-gpu-preemption x` разблокирует без патча.
3. Контроль состояния: `fastboot getvar unlocked` (строка `unlocked` в образе есть; поддержка getvar-пути проверится там же).

## 5. Открытые вопросы

| Вопрос | Что нужно |
|---|---|
| Полярность/семантика типов 5/6/7/9 | выведена статически из таблицы 0x5c710 и сеттеров; подтвердится тестом B (тип 6 синтезируется guard-ом после прошивки — ожидаемо «lock») |
| Назначение поля devinfo 0x90 = 1 | раскладка на диске (is_unlocked @0x10?) vs RAM-структура (+0x0d) транскодируется VB-драйвером; точное смещение on-disk не установлено |
| Верифицирует ли VB-драйвер хэш в devinfo | определяет, была бы вообще возможна «простая» правка devinfo; для варианта A не важно |
| Как именно регистрируется таблица 0x5eae8 | трасса FastbootLib-протокола не дочитана (рутинный рантайм-вызов); на выводы не влияет |
| Проверяет ли XBL подпись abl | решается переподписанием тестовым ключом или эмпирически (тест на неактивном слоте) |

## 7. Вывод одной строкой

Unlock-команды **вырезаны** из интерфейса стокового ABL (строки + регистрация), но **движок разблокировки цел и спрятан**: типы команд 5/6/7/9 диспетчера ведут на живую цепочку записи `is_unlocked` с сохранением через VB-протокол в devinfo; разблокировка без ручной правки devinfo — либо (гипотеза, проверить первой) `fastboot oem set-gpu-preemption` прямо сейчас, либо 12-байтовый патч `abl_a/abl_b`, после которого ABL сам выполнит легальный unlock.
