# Гипотезная рамка: побайтовая раскладка Client Votes (vlow)

Локальный анализ измеренных значений — подготовлено к сопоставлению с downstream-
картой битов (поиск запущен 2026-11-15). Все значения — u32, байты LSB-first:
`0xAABBCCDD` → b0=DD b1=CC b2=BB b3=AA.

## Измеренные точки

| Состояние | u32 | b3 b2 b1 b0 (LSB-first) |
|---|---|---|
| awake settled, радио on | 0x87838783 | 87 83 87 83 |
| awake дрейф между циклами | 0x83818381 | 83 81 83 81 |
| awake дрейф (вариант) | 0x81838183 | 81 83 81 83 |
| awake, wifi off (+bt off) | 0x83878381 | 83 87 83 81 |
| noirq-пол, радио on | 0x83878381 | 83 87 83 81 |
| noirq-пол, радио off | 0x85818581 | 85 81 85 81 |
| истинный пол сна (13.11) | 0x00000081 | 00 00 00 81 |

## Наблюдения

1. **Алфавит каждого байта: {0x81, 0x83, 0x85, 0x87, 0x00}** = бит7 (всегда, кроме
   полного нуля в глубоком сне у трёх байтов) + подмножество {бит0, бит1, бит2}.
   Т.е. на байт — до трёх «воксеров» + один постоянный бит7.
2. **Три байта в истинном сне обнуляются полностью** (включая бит7!) — их бит7 не
   константа, а чей-то голос («система активна» класса APSS?). Остаётся только
   b0=0x81: бит0 + бит7.
3. **Дрейф awake-значений** — 0x83818381 ↔ 0x81838183 — это НЕ ротация u32, а
   симметричная перестановка пары байтов (81↔83): похоже на два байта-близнеца
   (одинаковая семантика, зеркальное состояние) — кандидаты: CX/MX или APSS-пара.
4. **wifi off меняет b1 81→87** (добавляет биты 1,2) — контринтуитивно: rfkill
   ДОБАВЛЯЕТ голоса в этом байте. Либо b1 — не «радио», либо rfkill поднимает
   компенсирующий голос (например, hold-голос при закрытии wlan-пути).
5. **noirq-пол с радио off** (85 81 85 81) vs **радио on** (83 87 83 81): байтовые
   пары (b3,b1) и (b2,b0) меняются согласованными парами → фактически две
   независимые ГРУППЫ по два байта: группа A={b0,b2}, группа B={b1,b3}.
6. vmin-запись (append) всегда 0x0 — либо не пишется, либо vmin-режим так далеко,
   что статистика не доходит.

## Ответ downstream-карты (пришёл 2026-11-15, полный отчёт — DOWNSTREAM-DECODE.md)

- Публичной таблицы нет — декод в закрытой rpm_proc. Семантика от Maulik Shah (QTI,
  LKML 2021, thread по qcm2290): **«Client votes are history of client votes on xo.
  Each byte represents xo clock votes from subsystems»** — u32 = 4-байтная история
  (или байт-на-мастер APSS/MPSS/ADSP/CDSP; «TZ covered by APSS»).
- vlow == xosd == XO-off на уровне SoC; vmin = vlow + минимизация рельсов.
  Вход: все подсистемы в power down + sleep-голоса позволяют + достаточное время сна.
- Бит7 в каждом ненулевом байте на трёх платформах — маркер валидности, не блокер.
  Биты 0-2 — накапливающиеся блокеры. Наш 0x81 = одна группа (≈APSS) держит XO-голос.
- **Главный чинимый кандидат: `clk_smd_rpm_handoff()`** — proxy-голоса INT_MAX в оба
  сета за каждую клоку; апстрим-патч «Skip proxy votes on clocks for QCM2290»
  (Imran Shaik, не влит) применим к khaje. Наше дерево (7.3.1) — безусловно handoff.
- Наш bi_tcxo в clk_summary: prepare=27 (remoteproc'ы, UFS, USB PHY, SDC...) — это
  APSS-сторона; rpm sleep-голоса за ними clk_summary не показывает.
- Сток (день 2+) тоже vlow=0/xo=0 — но его suspend с adb не прошёл ни разу, так что
  строго «потолок прошивки» не доказан; у mainline есть конкретный кандидат на фикс.

## Эксперименты-кандидаты после карты

- выключение модема (rc-service modemmanager stop + rfkill wwan, если есть) →
  какой байт/бит снимается;
- bootloader-прогрев без ADSP (disable remoteproc) → банк ADSP;
- сравнение с qcm2290-агатти (та же прошивка RPM?) — если есть живой agatti.
